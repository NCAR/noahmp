# Spec: add a coupled variable across the Noah-MP ↔ ERF boundary

> Status: living workflow · Owns: the *interface* of a variable — where it is
> declared and how it is wired. It does **not** own the physics that fills it.
> Companion: [`spec-fc-api.md`](spec-fc-api.md) (the generator),
> [`spec-io-parallel.md`](spec-io-parallel.md) (Step 4, output).
> Public docs: <https://erf.readthedocs.io/en/latest/CouplingToNoahMP.html>

## Purpose

Expose a new variable across the C++ ↔ Fortran coupling boundary, and optionally
get it allocated, namelist-guarded, and written to the NetCDF land output. Only
edit the files named below.

## The single source of truth

The C ↔ Fortran glue is **generated** from one place: the `@NoahmpMacro:Source {
… }` block (the member declarations of `class NoahmpIO_type`) in `NoahmpIO.H-mc`.
The **order** of members there *is* the ABI order. One annotated declaration
expands into every place the shared-memory ABI needs it. Only the tracked `*-mc`
templates are hand-edited; the targets are gitignored and regenerated by the
build. See [`spec-fc-api.md`](spec-fc-api.md) for the full mechanism.

## Step 1 — declare it in the Source block

Add **one** line to `@NoahmpMacro:Source` in `NoahmpIO.H-mc`, in the ABI position
you want (order in the block = ABI order):

```cpp
noahmp_real RAINBL;                    // @NoahmpMacro:scalar doc="rainfall [mm]"
NoahmpArray2D<noahmp_real> RAINLSM;    // @NoahmpMacro:bounds_2d(xstart:xend, ystart:yend) doc="lsm rain"
NoahmpArray3D<noahmp_real> SMOIS;      // @NoahmpMacro:bounds_3d(xstart:xend, nsoil:nsoil, ystart:yend)
```

Rules (the generator errors loudly otherwise — see
[`spec-fc-api.md`](spec-fc-api.md) §4):

- Kind is **inferred** from the C++ type (`int` / `noahmp_real` /
  `NoahmpArray{2,3}D`).
- Arrays need `@NoahmpMacro:bounds_{2,3}d(lo:hi, …)` in **Fortran order**; rank
  must match the type and pair count. Every bound token must be a **literal** or
  a **coupled member name** (`xstart`, `xend`, `kms`, `kme`, `nsoil`, `numrad`,
  …) — never a Fortran-only parameter. Optional `doc="…"`.
- Scalars carry `@NoahmpMacro:scalar` and optional `doc`.
- Ints need no annotation (`int a, b, c;`); an optional C++ default is shared with
  Fortran (`int numrad = 2;`).
- Use `noahmp_real` / `c_kind_noahmp`, **never** a hardcoded `double` / `C_DOUBLE`.

## Step 2 — regenerate

```sh
make codegen          # or: cmake --build <dir> --target noahmp_codegen
make codegen-check    # or: ...noahmp_codegen_check   -- exit 1 on drift (CI)
```

A plain `make` / `cmake --build` also regenerates before compiling.

## Step 3 — manual (non-boundary) runtime wiring

The generator emits the member declarations, all ABI plumbing, **and** the
Fortran `allocate()` of each coupled array (bounds come straight from the
`bounds_Nd` annotation). It does **not** touch the rest of the runtime:

- **Arrays**: nothing — the allocate is generated. (Scalars are never allocated;
  they point at C++-owned storage.)
- **Namelist-guarded scalar** (only for a scalar *also* read from the Fortran
  namelist) — in `NoahmpReadNamelistMod.F90`:
  ```fortran
  if (NoahmpIO%name == undefined_real) NoahmpIO%name = name
  ```
  so a C++-API value wins over the namelist default (`undefined_real = -9999.0`,
  the same sentinel the C++ member is initialized to).

## Step 4 (optional) — expose it to the NetCDF land output

If the variable should appear in the per-step land output, add it to
`NoahmpWriteLandMod.F90` (not generated — edit directly), following the §4 steps
of [`spec-io-parallel.md`](spec-io-parallel.md). To carry it across
**restart** instead, see [`spec-io-restart.md`](spec-io-restart.md) §6.

## Validation

- `make codegen-check` passes (all targets, incl. the array `allocate()`, in sync
  with the Source block);
- any namelist-read scalar has its sentinel-guarded assignment;
- (if output wanted) the variable is defined **and** written with matching dims;
- the project builds and `NoahmpIO_AssertAbi()` does not abort.

## If the generator can't express what you need

If a variable needs a *kind* of binding the generator cannot emit yet, extend the
generator first ([`spec-fc-api.md`](spec-fc-api.md) §4 — add an annotation
kind/region), keeping the one-line-edit promise and the ABI guarantees intact,
then return here.
